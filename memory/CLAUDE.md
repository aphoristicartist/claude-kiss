## Compact Instructions

Create a concise implementation handoff, not a narrative history.

Preserve:

- The user's current objective, acceptance criteria, and explicit constraints.
- Important design invariants, decisions, rejected approaches, and their reasons.
- Files created or changed, with paths and the still-relevant portion of each change.
- Current repository/worktree state and any user edits that must not be overwritten.
- Required test coverage, including behavior and edge cases already covered or still missing.
- Exact failures or diagnostics already encountered and how they were resolved.
- Remaining steps, assumptions, risks, and validation still required.
- Exact successful or failed validation commands and their meaningful results.

Omit:

- Full file contents, stale command output, and already-solved exploration dead ends.
- Marketing, greetings, apologies, generic advice, and unrelated repository findings.

Never invent completed work, approvals, test results, or user requests.
